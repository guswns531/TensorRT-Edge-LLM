# v0.11.0 Port, Milestone 1: Merged Tree Builds and Passes Tests

## Outcome

Branch `codex/v0110-phase-forward-port` merges upstream v0.11.0 (`95515c2`) into the phase-serving fork (`fca7bd0`)
with a real merge commit (`83f5f768`; merge base v0.10.1 `e8b2952`), followed by regression fixes. The tree builds
every required target (plugin, `llm_build`, `llm_inference`, `llm_bench`, `visual_build`, `llm_phase_context_smoke`,
12 unit-test executables) with `-DENABLE_CUTE_DSL=ALL` on SM86.

- C++ unit tests: 0 failures in all 12 executables (skips are 2-GPU NCCL and other-SM kernel variants).
- `tests/python-unittests/test_attention_plugin.py`: 144 passed, 1 failed, 13 skipped. The failure
  (`test_head512_shared_vision_prefill_uses_token_aligned_rope`, cos_sim 0.9926) fails identically on clean v0.11.0.

No engines were exported or built from this tree yet; serving behavior and performance are unvalidated.

## Process

47 conflicted files were resolved in six sequential subsystem passes on one in-progress merge (kernels/attention
plugin; KV/state/config/exec; runtime core; builder and ViT runners; Python exporter; CMake/examples/build), then two
fix passes. Per-file decisions are in note 372 (the resolution log). The main structural change absorbed from upstream
is the token-major 2D ragged ABI for packed QKV/embeds, which the fork's packed prefill, builder profiles, and
exporter were re-expressed on.

## Fork behavior changes to watch in milestone 2

- `KVPageTable` uses upstream's single-buffer dirty-index upload instead of the fork's triple-buffered async upload
  (needed for bounded SWA windows): possible host-side cost.
- Phase-scoped `PipelineIO` allocates both phase-sized dense tensors and full-capacity ragged tensors: possible
  memory growth on the 10 GiB GPU.
- `Gemma4ResizeScratch` (pooled vision resize/normalize scratch) is gone; Gemma4 image preprocessing uses upstream's
  shared `resizeAndNormalizeToRgb`.
- Vision-block ids are generated on the GPU (upstream path) instead of the fork's host round trip.
- INT4 export: V2 (CuTe DSL) is the exporter default; the fork's validated V1 path is
  `--int4_gemm_plugin_version 1 --externalize-weights int4_ffn`.

## Regression fixes after the merge

- Zero-volume optional `kv_cache_start_idx` bindings are treated as absent (TensorRT may pass a non-null pointer).
- Pure shared-KV RoPE no longer adds the donor start index a second time (rope rows are pre-gathered per token).
- Packed-prefill dense/packed helpers receive a flat single-row view under the ragged ABI.
- Unit tests updated where upstream intentionally changed contracts (always-present ragged registry tensors,
  token-major PLE views, non-moving batch compaction, new required `PipelineIO` fields).
