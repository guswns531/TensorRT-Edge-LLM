# Thor Qwen3.8 final D64 vs vLLM c64 comparison

## Fairness contract

- 128 requests, concurrency 64
- short `128->64`, wave `256->96`, decode-heavy `128->256`
- streaming, greedy, ignore EOS, fixed output length
- prefix caching and speculative decoding disabled
- one warmup followed by three runs
- locked GPU 1.575 GHz and EMC 4.266 GHz
- Phase P4/D64 versus stock vLLM 26.06 NVFP4, FP8 KV, async scheduling, CUDA graphs
- every run completed 128/128 requests

## Median throughput

| workload | Phase D64 | vLLM vanilla | Phase vs vLLM |
| --- | ---: | ---: | ---: |
| short burst c64 | 203.40 tok/s | 235.27 tok/s | -13.55% |
| wave burst c64 | 245.56 tok/s | 256.56 tok/s | -4.29% |
| decode heavy c64 | 307.90 tok/s | 333.19 tok/s | -7.59% |

At equal c64 load, vLLM wins total throughput in all three workloads. The earlier Phase victory remains valid only for the
locked c32 comparison: Phase D32 beat vLLM c32 because the previous vLLM run reached only about 97-101 tok/s. vLLM scales
much more effectively from c32 to c64.

## Latency trade-off

| workload | Phase TTFT / TPOT / E2E | vLLM TTFT / TPOT / E2E |
| --- | --- | --- |
| short | 1,993 / 287 / 20,086 ms | 2,515 / 235 / 17,335 ms |
| wave | 1,949 / 234 / 24,691 ms | 2,606 / 220 / 23,272 ms |
| decode heavy | 1,807 / 201 / 53,170 ms | 2,172 / 184 / 49,103 ms |

Phase provides 16.8-25.2% better median TTFT, but vLLM has better TPOT, E2E, and throughput. The Phase scheduler admits
prefill earlier while its D64 decode step remains slower.

## Power

Phase D64 mean/max GPU power was 40.5/79.4 W and mean board input was 95.3 W. vLLM mean/max GPU power was 35.9/62.6 W
and mean board input was 90.3 W. vLLM is also more energy-efficient in this c64 campaign.

## Conclusion

The D64 optimization is a real 29.8-44.5% improvement over Phase D32, but it does not surpass the best vanilla vLLM c64
configuration. The next performance target is no longer scheduler batching. Nsight attributes 33.6% to GDN and roughly
34% to underfilled NVFP4 GEMMs. Matching vLLM requires a faster D64 GDN small-grid runtime symbol and/or an M64-specialized
NVFP4 linear kernel while preserving Phase's TTFT advantage.
